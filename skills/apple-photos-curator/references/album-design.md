# Album design rules

## Use complementary dimensions

- **Time and events:** years, holidays, life stages, visits, trips.
- **People:** individuals, pairs, families, group photos.
- **Places:** countries, cities, recurring visits, meaningful local places.
- **Sources:** phones, cameras, storage cards, imports, migrations.
- **Media and purpose:** screenshots, documents, videos, Live Photos, favorites, review queues.

An asset may belong to several dimensions without creating media copies.

## Naming

Use sortable, human-readable titles:

```text
NN_emoji Place or theme · Visit or context · YYYY–YYYY
NN_emoji Person group · Memory type
NN_emoji Source · Import batch · YYYY-MM-DD
```

Use the locally verified place or campus name. Do not infer a formal name from proximity alone.

## Split and merge

- Split a recurring city by non-overlapping visit periods when one album becomes difficult to browse.
- Split a university, residence, or recurring place by stable campus/site boundaries when local location evidence supports it.
- Keep an optional all-sites overview if it remains useful; document that detailed albums intentionally overlap it.
- Merge adjacent GPS clusters when contact sheets show one real place.
- Avoid independent albums for tiny weak candidates. Keep them in a city or time album until more evidence arrives.
- Prefer fewer meaningful albums over exhaustive micro-classification.

## Folder depth and iOS covers

- Keep primary browsing paths shallow.
- Use a folder when it owns several durable child albums.
- Do not create fake or empty albums to fill a four-tile folder cover.
- If a folder has fewer than four meaningful children, flatten it when that improves navigation.
- More than four child albums is acceptable; only the visible cover tiles are limited.

## Review queues

Review queues are temporary operational views, not permanent taxonomy:

- location pending review;
- low-value candidates for manual deletion;
- unclassified screenshots;
- unresolved imports;
- possible duplicates awaiting exact verification.

Never label old, blurry, low-resolution, or OCR-missing media as disposable without content review.
